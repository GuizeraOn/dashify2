<task type="auto">

  <files>scripts/migrate-sheets-to-supabase.mjs</files>
  <read_first>.planning/phases/06-migracao-de-dados-historicos/06-RESEARCH.md, lib/parsers/vendas.ts, lib/parsers/perfectpay.ts</read_first>
  <action>
Criar `scripts/migrate-sheets-to-supabase.mjs` com as seguintes funcionalidades:
1. Conexão autenticada ao Google Sheets via `googleapis` usando `GOOGLE_SERVICE_ACCOUNT_JSON` e `SPREADSHEET_ID`.
2. Conexão ao Supabase com `createClient(NEXT_PUBLIC_SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY)`.
3. Verificação de integridade da tabela `sales`: tentar selecionar 1 linha. Se a tabela não existir (`PGRST205`), emitir mensagem clara solicitando a execução de `supabase_vendas.sql` no SQL Editor do Supabase e abortar com código 1.
4. Carregamento de dados auxiliares:
   - Consulta ao catálogo de produtos em `app_settings` (chave `product_codes`).
   - Leitura de `Log_Webhooks!C:C` criando um dicionário de payloads por código de venda (`payload.code`).
5. Leitura de `DB_Vendas!A:W`:
   - Filtrar linhas em branco e cabeçalho, isolando exatamente as 1.058 transações não-vazias.
   - Conversor de data flexível suportando `YYYY-MM-DD HH:mm:ss` e `DD/MM/YYYY HH:mm:ss`, gerando ISO string com timezone de São Paulo (`-03:00`).
   - Mapeamento robusto para os campos de `SalesRow`:
     - `code`: `row[3].trim()`
     - `date`: data formatada em ISO
     - `date_created`: data em ISO
     - `date_approved`: data em ISO se status for aprovado, caso contrário null
     - `customer_name`: `row[7]`
     - `customer_email`: `row[8]`
     - `customer_phone`: `row[9]`
     - `country`: normalizado com `normalizeCountry`
     - `product_name`: `row[4]`
     - `product_code`: código do produto via catálogo ou log, se encontrado
     - `funnel_step`: `row[5]`
     - `gross_revenue_brl`: `parseFloatSafe(row[17])`
     - `net_revenue_brl`: `parseFloatSafe(row[18])`
     - `payment_method`: `row[11].toLowerCase()`
     - `status`: 'aprovado' se row[12] for 'Aprovado', 'cancelado' se 'Cancelado', 'reembolsado' se 'Reembolsado', 'aguardando' se 'Pendente' ou 'Aguardando Pagamento', 'outro' se 'Abandono'
     - `sale_status_enum`: número correspondente (2 para aprovado, 6 cancelado, 7 reembolsado, 1 aguardando, 12 outro)
     - `sale_status_detail`: valor textual original de `row[12]`
     - `utm_source`: `row[15]`
     - `utm_campaign`: `row[19]`
     - `utm_medium`: `row[20]`
     - `utm_content`: `row[21]`
     - `utm_term`: `row[22]`
     - `raw_payload`: payload do `Log_Webhooks` ou objeto sintético `{ source: 'sheets_migration', row_original: ... }`
6. Ingestão em lote no Supabase em chunks de 200 registros (`upsert` com `onConflict: 'code'`).
7. Auditoria de paridade pós-migração:
   - Query no Supabase contando o total de vendas aprovadas e somando `net_revenue_brl`.
   - Comparação contra os valores esperados da planilha:
     - Total de vendas aprovadas: 723
     - Total de faturamento líquido: R$ 62.010,30
   - Se os números baterem, exibir relatório formatado de sucesso e sair com código 0.
  </action>
