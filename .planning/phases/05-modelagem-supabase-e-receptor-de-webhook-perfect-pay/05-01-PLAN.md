   - `date TIMESTAMP WITH TIME ZONE NOT NULL`: data do evento ou aprovação
   - `date_created TIMESTAMP WITH TIME ZONE`: data de criação do pedido

   - `installments INTEGER DEFAULT 1`
   - `payment_method TEXT`: normalizado ('cartão de crédito', 'boleto bancário', 'pix')

Criar `lib/parsers/perfectpay.ts`:
1. Mapeamento de `sale_status_enum` para string amigável:
   - 1 -> 'aguardando'
   - 2, 8, 10 -> 'aprovado'
   - 6 -> 'cancelado'
   - 7 -> 'reembolsado'
   - 9 -> 'estornado'
   - 5, 11 -> 'recusado'
   - outros -> 'outro'
2. Mapeamento de meio de pagamento (`payment_type_enum` e `payment_method_enum`):
   - se texto ou enums indicarem boleto/ticket -> 'boleto' ou 'boleto bancário'
   - se indicarem cartão/credit_card -> 'cartão de crédito'
   - se indicarem pix -> 'pix'
3. Extração e cálculo de faturamento líquido (`net_revenue_brl`):
   - Buscar comissão do produtor (`affiliation_type_enum === 1`).
   - Se encontrar, usar `commission_amount`.
   - Se não encontrar, usar `sale_amount` subtraindo a taxa da plataforma (`affiliation_type_enum === 0`) e afiliados (`affiliation_type_enum === 5`).
   - Se não houver array de comissão, fallback para `sale_amount`.
4. Normalização de país:
   - Reutilizar a tabela de países de `lib/parsers/vendas.ts` para converter códigos ISO (ex: 'BR' -> 'Brasil', 'US' -> 'Estados Unidos', etc.).
5. Telefone: concatenar `phone_area_code` e `phone_number`.
6. Função principal `parsePerfectPayPayload(payload: PerfectPayWebhookPayload): SalesRow`.
